# 对齐阶段自动搜索并执行多段 MoveL

本模式在原来的 Y/Z 对齐直线不可行时，搜索有限组中间点并执行通过检查的路线。仍用 `rm_driver` 的绝对 MoveL；不启动 MoveIt，不调用 MoveJ，不改变最终对齐目标与朝向。后面的接近、夹紧、旋转和撤退逻辑不变。

## 启动

`direct_driver_bringup.launch.py` 已默认使用自动绕行配置，直接启动即可：

```bash
ros2 launch realman_gemini_cabinet direct_driver_bringup.launch.py
```

原 named-panel、panel-layout、仅预检查模式均保留，可通过 task_config 显式选择。新配置继承现场当前动作参数，包括 0.3 m 撤退距离。

## 路线选择

1. 从实际关节角和实际末端位姿开始，先检查原 Y/Z 路线；可行则直接使用原路线。
2. 若不可行，尝试交换轴顺序，以及“先下降、再横移、最后升至原目标”的三段 MoveL。
3. 不额外沿 X 轴靠近柜体，不改变朝向，不替换起始关节解。每段逐点连续求解，使用上一点的关节解作为下一点的种子。
4. 检查逆解、模型关节限位、余量、关节跳变、正逆解一致性及厂家模型中的机械臂自碰撞。
5. 在通过检查的候选中优先选择路程较短的，路程相同优先选最小关节余量较大的。
6. 开始执行前整条路线必须通过；每段执行前从最新回读状态复查剩余路线。每段结束核对末端位置、朝向、关节构型，累计偏差不能改变原对齐目标。

关节角在路线上连续变化，没有中途切换到另一个不连续的逆解分支。通过 MoveL 绕行，关节可沿另一方向连续到达相同末端目标。

## 范围参数与现场条件

```yaml
alignment_reroute: true
alignment_reroute_drop_clearance_m: 0.10
alignment_preflight: true
alignment_preflight_step_m: 0.001
alignment_preflight_min_margin_deg: 5.0
alignment_preflight_max_joint_step_deg: 5.0
```

用户已确认原观察位下方约 10 cm 有足够空间。`drop_clearance_m` 是这个现场自由空间约束，不是算法测量值；程序在下边界内预留 2 mm，最大下降候选为 98 mm。默认尝试下降 25、50、75、98 mm，最终返回原目标高度。技能参数默认仍为关闭；该启动文件默认加载的新任务配置会启用自动绕行。改变现场空间后，应相应更新允许下降范围。

自碰撞检查来自 RM63 III 标准版出厂算法模型，不包含完整的夹爪、相机、线缆及柜体环境碰撞模型。环境空间依据用户的现场确认，而非自动建图。5° 余量和每毫米最大 5° 变化是可配置的保守筛选阈值，不能替代实际控制器标定、动力学或环境验证。

搜索是有边界的候选搜索，不能保证任何停车姿态下都有路线。实际状态超出算法模型范围、模型与回读不一致、反馈失效或没有通过检查的候选时，仍会拒绝执行；不会扩大控制器限位或盲目重试。

在独立 ROS 域中，使用厂家 SDK 和合成反馈，验证了搜索、三段执行调度、段间回读检查、最终目标一致。此验证使用模拟执行器，不是实机运动测试。现场执行时会根据当时实际关节状态重新搜索，不复用这组历史角度。

`/rg_cabinet/status` 发布路线候选、选中路线及逐段执行结果。异常响应的 `alignment_preflight` 中保留相关诊断。原预检查模式使用说明见 `ALIGNMENT_PREFLIGHT.md`。
